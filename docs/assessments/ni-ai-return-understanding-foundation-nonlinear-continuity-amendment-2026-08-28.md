## Purpose

This amendment integrates a relationship exposed after A20 outcome reconciliation and A21 language / linguistic semantic-fidelity formalization.

It does not create a new runtime mechanism. It clarifies how a governed architecture may preserve understanding across return, movement, representation change, and reassessment without allowing any of those functions to silently become authority.

## 1. Return with understanding

A governed return should not be reduced to an opaque success signal or raw output where consequential reassessment depends on knowing what occurred and how it was understood.

Where proportionate to consequence, the return path may preserve:

```text
AUTHORIZED ACTION
-> OBSERVED RESULT
-> SOURCE / PROVENANCE
-> WHAT WAS UNDERSTOOD
-> WHAT WAS INFERRED
-> WHAT CHANGED
-> WHAT REMAINS UNCERTAIN
-> DISCREPANCIES / SIDE EFFECTS
-> CURRENT CONDITIONS
-> RETURN
-> REASSESSMENT
```

The returned understanding remains bounded interpretation. It does not become authority merely because it is preserved or useful.

```text
RETURNED RESULT != VERIFIED GOVERNED OUTCOME
RETURNED UNDERSTANDING != SOURCE INTENT AUTOMATICALLY
UNDERSTANDING != AUTHORITY
RETURN != REAUTHORIZATION
```

A20 governs observed outcome and reconciliation. A21 governs the fidelity of the language and representation used to carry meaning through that return.

## 2. Architectural foundation

A foundation is not merely the first component in a sequence.

A governed architectural foundation preserves the relationships that make later states, interfaces, interpretations, and actions comparable to a common reference.

A sufficiently attributable foundation may preserve:

```text
SOURCE MEANING
-> GOVERNING INVARIANTS
-> RESPONSIBILITY BOUNDARIES
-> AUTHORITY / PERMISSION SEPARATION
-> PROVENANCE
-> INTERFACE CONTRACTS
-> RETURN / REASSESSMENT EXPECTATION
```

The architectural principle is:

> **A foundation does not need to prescribe every future path; it must preserve enough governing relationship for later paths to remain comparable, correctable, and reassessable.**

Therefore:

```text
FOUNDATION != RIGID SEQUENCE
FOUNDATION != PERMANENT AUTHORITY
FOUNDATION != COMPLETE IMPLEMENTATION

FOUNDATION
-> REFERENCE
-> COHERENCE
-> COMPARISON
-> CORRECTION
-> REASSESSMENT
```

## 3. Non-linear movement

Governed work does not have to move in one straight line.

Evidence may reopen an earlier question. A later result may require return to an earlier checkpoint. A different interface may expose a relationship that was present but not yet legible. A representation may change while the underlying governed relationship remains attributable.

Accordingly:

```text
NON-LINEAR MOVEMENT != UNGOVERNED MOVEMENT
BRANCHING != AUTHORITY EXPANSION
RETURNING TO AN EARLIER CHECKPOINT != FAILURE
REPRESENTATION CHANGE != MEANING CHANGE AUTOMATICALLY
TOOL CHANGE != AUTHORITY TRANSFER
INTERFACE CHANGE != SOURCE REPLACEMENT
```

The governing requirement is traceability:

```text
FOUNDATION
-> CURRENT CHECKPOINT
-> MOVEMENT / BRANCH
-> PRESERVED PROVENANCE
-> SEMANTIC-FIDELITY CHECK
-> CURRENT AUTHORITY / PERMISSION CHECK
-> NEXT LEGITIMATE STATE
```

Movement may therefore be non-linear while meaning, provenance, and authority remain traceable.

## 4. Interface correspondence

Different tools may organize the same governed work differently.

A document surface may preserve narrative structure. A work-management surface may preserve tasks, dependencies, status, or branching movement. A repository may preserve exact artifacts, diffs, and checkpoints.

No interface becomes the source of authority merely because it represents the work effectively.

```text
DOCUMENT STRUCTURE != SOURCE AUTHORITY
TASK GRAPH != GOVERNING MEANING
REPOSITORY CHECKPOINT != HUMAN INTENT
INTERFACE EFFICIENCY != PERMISSION
```

A21 applies whenever wording, labels, summaries, classifications, or schema fields transform the representation while the governed relationship moves between surfaces.

## 5. Time, place, and current conditions

A governed relationship may depend on when and where it applies, as well as the material conditions present at that boundary.

The concise principle is:

> **Time and place are applicability conditions, not automatic sources of authority.**

Therefore:

```text
PAST VALIDITY != PRESENT VALIDITY
VALID HERE != VALID EVERYWHERE
CURRENT CONTEXT != UNIVERSAL CONTEXT
LOCATION != AUTHORITY BY ITSELF
TIMING != PERMISSION BY ITSELF
URGENCY != AUTHORITY
```

Where time, jurisdiction, environment, location, channel, or other situational conditions materially affect a consequential action, those conditions must be checked as part of currentness, scope, permission, execution binding, and reassessment.

This extends rather than replaces A15 freshness / expiration and A19 execution binding.

## 6. Integrated relationship

The clarified thesis relationship is:

```text
FOUNDATION
-> MEANING / INVARIANTS / BOUNDARIES
-> REPRESENTATION
-> GOVERNED MOVEMENT
-> CURRENT TIME / PLACE / CONDITIONS
-> AUTHORITY / PERMISSION CHECK
-> EXECUTION BINDING
-> ACTION OR NO-ACTION
-> OBSERVED RESULT
-> RETURN WITH ATTRIBUTABLE UNDERSTANDING
-> SEMANTIC-FIDELITY CHECK
-> REASSESSMENT
-> NEXT LEGITIMATE STATE OR STOP
```

This sequence may be traversed non-linearly. The arrows indicate governed correspondence, not automatic inheritance of authority.

## Boundary

This amendment does **not** authorize:

- runtime activation;
- external execution;
- automatic movement between tools or systems;
- treating returned understanding as source intent or authority;
- treating a foundation as permanent permission;
- treating non-linear movement as permission to bypass checkpoints;
- treating time, place, urgency, or environment as authority by themselves;
- automatic acceptance of semantic interpretation;
- any change to the existing SAL validation result.
