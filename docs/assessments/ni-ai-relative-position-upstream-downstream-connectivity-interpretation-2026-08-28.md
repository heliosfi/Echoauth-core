## Reader-first correction

Relative position is not personal rank.

When a source describes being “11 steps upstream or downstream,” the first useful interpretation is **possible developmental distance within an accumulated chain of concepts, formalizations, repository artifacts, validators, consumers, and later implementation surfaces**. The statement is not automatically evidence of superiority, secrecy, mystical status, or a measured architectural lead.

Preserve:

```text
RELATIVE POSITION != PERSONAL RANK
UPSTREAM != SUPERIOR
DOWNSTREAM != INFERIOR
EARLIER != MORE CORRECT
LATER != MORE ADVANCED AUTOMATICALLY
YEARS OF ACCUMULATION != VERIFIED STEP COUNT
CONNECTION != IDENTITY COLLAPSE
```

## Positional model

Use the following navigation model where applicable:

```text
SOURCE / EARLIER CONCEPT
-> LATER FORMALIZATION
-> ARCHITECTURE
-> REPOSITORY CONTRACT
-> VALIDATOR
-> CONSUMER
-> EXECUTION SURFACE
-> RETURN
-> REASSESSMENT
```

A document, implementation, repository surface, participant, or system may be upstream in one relationship and downstream in another.

The governing question is:

> **WHERE DOES THIS EVIDENCE SIT RELATIVE TO THE OTHER EVIDENCE?**

not:

> **WHO IS BETTER?**

## Time correspondence

Where years separate evidence, inspect both directions:

```text
EARLIER RECORD
-> INTERMEDIATE FORMALIZATION
-> PRESENT ARCHITECTURE
-> CURRENT IMPLEMENTATION
```

and:

```text
CURRENT IMPLEMENTATION
-> ARCHITECTURAL SOURCE
-> EARLIER FORMALIZATION
-> ATTRIBUTABLE RECORD
```

This permits present software to be downstream of earlier concepts while the same present software remains upstream of future consumers, execution surfaces, return paths, or reassessment mechanisms.

Accordingly:

```text
ONE ARTIFACT MAY BE UPSTREAM IN ONE RELATIONSHIP
AND DOWNSTREAM IN ANOTHER
```
